# Methods-first benchmark preparation

Successor operating addendum to the pinned agent-assisted review skill, 15 October 2026. The original skill/release manifest remains unchanged. Repeated candidate qualification exposed a concrete waste/error risk: retrieving trial sets before distinguishing OR from RR, fixed Mantel–Haenszel from fixed inverse variance, and random-effects estimators.

Use `scripts.qualify_benchmark_method` before spending the primary-retrieval/model budget. Supply a candidate ID, complete declared published-analysis scope, original review text/URL/hash, exact located quotations, declared design and five method dimensions. `basis=explicit_source` means an agent read and transcribed that assertion; software names, package defaults, and matching pooled numbers do not establish it. Unknown fields remain unknown. This is agent-assisted reading, not independent semantic verification. A literal quotation can be correctly anchored but misinterpreted; the operator remains responsible for the mapping and scientific contract.

Run from an immutable package using `scripts.run_frozen.bundle` and `command`. The real commands and examples are saved in `data/benchmarks/release_candidate_qualification_v2/execution_receipt.json` and its two manifests. The command requires a new output directory. It checks source text hashes/anchors, exact declared engine compatibility and supported design, then emits `qualification.json`. It performs no network/model calls and never launches an analysis. It is an explicit skill preparation entry point, not a retroactive gate injected into old frozen runners.

`primary_retrieval_ready=true` only advances to complete primary-set qualification. It does not establish source completeness, design truth, arm/time/outcome compatibility, independence, N, missing-data policy, zero-cell policy, integrity, statistical input variance or reference semantics. Those still require the normal review workflow and separately frozen scientific contract. `scientific_execution_authorized` is always false. A failed method check must not be bypassed by trimming contributors, changing effect measure, assuming software defaults, or finding an estimator that matches a published number.

Supported declarations currently cover fixed MH RR and inverse-variance MD/SMD with fixed or DerSimonian–Laird random effects and normal intervals. Continuous effect/variance definitions still require downstream checks; these broad labels alone do not prove complete method equivalence. Binary random effects and OR are not supported by this preparation policy. Implementing a new estimator requires primary methodological justification and separate tested policy, not adding a label to this table.
