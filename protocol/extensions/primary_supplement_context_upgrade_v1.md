# Primary supplement context upgrade v1

Normal primary-linked DOCX ingestion now records ordered paragraph/table blocks, explicit table cells, embedded-image relationship IDs/archive members/raw hashes and safe content-addressed assets. Context is appended to the ordinary document text consumed by extraction, not solely an unused sidecar. Image markers explicitly say pixels are preserved but not transcribed. Adjacency does not imply caption ownership. The context manifest identifies parser policy/raw DOCX hash and exact asset directory; image contents remain outside model input unless a separately supported consumer explicitly loads them.

Bound DOCX compressed/uncompressed sizes to20MB and archive members to2000; reject duplicate member/relationship IDs, entities, missing image relationships and unsafe relationship paths. External images are listed as not fetched. No ZIP paths are extracted to arbitrary filesystem paths. Formatting-run text is concatenated while preserving tabs/breaks and paragraph/table boundaries.

Existing cached documents remain unchanged. `upgrade_supplement_source` copies a pinned original source into a fresh destination, verifies original JATS PMID/PMCID, imports a retained HTTP200 article-specific supplement archive only when URL/hash match its receipt, and calls normal supplement augmentation in cache-only mode. It preserves previous primary/supplement snapshots, raw acquisition provenance and source hashes. Any prior augmented input is rebuilt from its preserved primary snapshot only in the new destination. Source-stage status is upgraded only when an ordered context is produced; it is not scientific review completion.

This changes source representation, not eligibility/statistics/accepted effects. Any subsequent scientific execution requires its own new pinned source/protocol/code contract. No guessed image values, review-target imports, numerical reruns or retroactive modifications. Model/numerical calls and network requests for preserved-archive replay are zero.
